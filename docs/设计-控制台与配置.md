# 控制台与配置 —— 设计记录

> 日期：2026-10-01
> 状态：已实现
> 承接"产品形态调整"讨论：装好即用的 neoagent、MC 式控制台、指令层统一、yml 配置。
> **命名红线**：用户可见面只有 neoagent；M/R/E 是内部模块代号，只活在代码与内部文档里。
> 前端决策：终端先行、网页留位（内核前端无关，网页将来是第二客户端）。

## 〇、命名红线（先立规矩）

- 用户可见面——控制台界面、help、报错、`/status`、config.yml 的键名与注释——
  一律说 **neoagent** 和大白话，不出现 M/R/E 等内部代号与内部行话：
  · `[M]` → `neoagent`；`R 整理完成` → `记忆整理完成`（或不进控制台）；
  · `recorder.pause_debounce_seconds` → `memory.tidy_delay` 这类键名清洗。
- 协议与存储里模型的内部代号**不动**（历史已定稿字节稳定、前缀缓存不能破），
  红线落在**渲染层**：显示时映射成 neoagent，零迁移成本。
- 人设文件是"写给模型的规格书"，协议术语可留；它对用户的自我介绍文案用 neoagent。

## 一、产品形态与进程模型

装好后一个命令 `neoagent`（`[project.scripts]` 入口；`python -m neoagent.run` 保留）：

- **`neoagent`（裸命令）= 一体化**：前台跑服务 + 自动连上自己的控制台，日常用；
  检测到服务已在跑 → 自动降级 attach（"已经在跑了，帮你连上"），永不双开；
- **`neoagent serve` = 无头服务**：纯日志（stdout 给 launchd/journald 收 + 落
  `logs/latest.log`），给"挂后台"的部署用；
- **`neoagent console`（别名 `neoagent tui`）= 控制台客户端**：随时 attach；
- 控制面 = 本机 socket（`data/control.sock`，0600）；**控制台永远是 socket 客户端**，
  一体化只是"服务恰好跑在旁边"——一套代码路径；
- 多终端同时 attach：看到同一份转录流，谁都能敲指令（单用户产品，不做权限）；
- Ctrl-C 语义：一体化 = 停服务退出；attach 的控制台 = 只断开自己（服务继续跑）；
  **`/stop` 才真正停服务**；
- macOS 用 launchd、Linux 用 systemd；`neoagent service install` 生成服务单元是后话。

## 二、三层信息模型（控制台 / 日志 / 账本）

之前把日志当控制台流是 MC 的遗产；拆开后各归各位：

| | 控制台（给主人看） | 日志（排障，基本没人看） |
|---|---|---|
| 对话消息（全频道，标来源） | ✅ 主体 | 不进 |
| 指令输入 + 回执 | ✅ | ✅ 一行摘要 |
| 需要主人动作的事：扫码、发送失败、配置写坏 | ✅ 系统通知 | ✅ |
| 生命周期：频道连上/断开 | ✅ 短通知 | ✅ |
| 工具调用工作行（一行一次，见第四节） | ✅ 可 `/quiet` | ✅ 完整 |
| LLM 用量、工具参数与结果全文、整理细节、trace | 不进 | ✅ 全量 |

- **账本**（turns/bubbles）= 模型上下文真值；**转录**（console 表）= 用户看到过什么；
  **日志** = 排障全量。三层各管各的，不混。
- **转录持久化**（`console` 表：时间/方向/频道/说话人/文本）：每条控制台输入、
  每条输出（消息、通知、工作行、指令回执）都落表；
  · 重新 `neoagent tui` → **回放全部历史**（`/history 100` 翻旧账），再接实时流；
  · 不在场也记：从控制台发消息后退出，neoagent 的回复照样落转录，回来就能看到；
  · 多终端 attach 共享同一份。
- `neoagent --verbose`：日志同时打进终端（开发用）；`/logs 50`：把最近 50 行
  技术日志临时调进控制台。

## 三、控制台观感（行式转录）

- **行式**，不是全屏 TUI：输出流 + 常驻 `>`（prompt_toolkit `patch_stdout`，
  输出重绘到提示行上方，输入行不花；↑ 历史、Tab 补全白送）。
  ⚠️ 必须 `patch_stdout(raw=True)`：默认会把 vt100 转义转义掉（ESC 变 `?`，
  颜色全丢；banner 在提示符前打印所以幸免——踩过，pty 实证过修复）。
  取舍不变：终端原生滚动/复制、多终端、QR、回放全免费；转录在服务端，
  将来换渲染端（网页）即可。
- **朴素原则**（避免"AI 味"的装饰）：
  · 无分割线、无图标字符（⚙ 之类）、不用 `·` 分隔、不用 `›`；
  · 正常标点随便用（冒号、括号、逗号），箭头 `→` 可用；
  · 不做补空格的列对齐：单空格分隔、左对齐自然流，每行自带时间戳不合并；
  · 颜色只承担语义不装饰：频道=青、neoagent=绿、说话人=粗白、时间/工具行=灰、
    正文=白（不着色）、异常=黄/红。
- **内容面（控制台区别于微信/飞书的点）**：全频道对话 + tool call 都显示——
  对话消费在微信/飞书，控制台是看它干活的窗口。
- 排版：`时间 频道 说话人: 正文`；回复关系用灰色"回复 xxx："文字前缀（不跨平台）；
  图片占位 `（图片 1 张）`（终端唯一硬缺口）。
- banner：保留 ASCII 文字 logo（绿→青渐变），logo 下两行普通文字（版本/配置路径/
  一句指引），只空行不画线；嫌吵可只在启动时显示。

## 四、工作行（工具与指令可见）

主人要能看到 agent 在执行什么工具：

- **行形**：`时间 工具名 参数  数据字段…`——无箭头、无结果摘要；
  参数单个裸值、多个 `k=v`（60 字符截断）；
- **数据字段是结构化数据**（工具构造处给出，渲染端不做任何文本解析），
  数字直接表述、不带中文量词：
  · `exec`：`0.4s exit 0`（秒一位小数、不足 0.1s 用 `45ms`；`exit N` 整段着色：
    0 绿 / 非 0 红）；
  · 写类（write_file/patch_file）：`+38 -2`（+ 绿 - 红）；查询类（read_file）：不带字段；
  · 失败/拒绝（任何工具）：`err <code>` 红（code 英文原样如 denied/bad_param，
    原因正文只进日志）；
- **agent 自调指令**（run_command）：指令行 + **完整工具返回**（与用户敲指令的回执
  同形，`系统: …`）；留审计；
- 结果正文不进控制台（细节 `/logs` / 日志文件）；不合并、不折叠；
  `/quiet` 收起工作行只留对话。

## 五、指令体系（一套注册表，两个前端）

- **语法两处完全统一**：`/` 开头 = 指令，裸输入 = 聊天。
  控制台裸输入 = 以主人身份跟 neoagent 说话，入账 `channel="cli"`（内置频道，
  `/home cli` 合法），回复打到所有连着的控制台；聊天里裸输入本来就是消息。
- 命令只写一份（注册表：名字/帮助/参数/权限档/处理函数），聊天与控制台各是前端：
  聊天回执 = `sender="system"` 真气泡（可引用、不进模型回合），控制台回执 = 打印行。

| 命令 | 聊天 | 控制台 | 作用 |
|---|---|---|---|
| `/help` | ✓ | ✓ | 用法 |
| `/home [channel]` | ✓ | ✓ | 主动消息默认出口 |
| `/status` | ✓ | ✓ | 频道连接 / 忙碌 / 今日用量 |
| `/effort <档>` | ✓ | ✓ | 思考档位热调 |
| `/connect <频道>` | — | ✓ | 扫码登录 + 启动 + 写自启 |
| `/disconnect <频道>` | — | ✓ | 停 + 取消自启（留登录态） |
| `/channels` | — | ✓ | 频道列表与状态 |
| `/logs [n]` | — | ✓ | 把最近 n 行技术日志调进控制台 |
| `/history [n]` | — | ✓ | 翻转录旧账 |
| `/quiet` | — | ✓ | 工作行收起/放开 |
| `/stop` | — | ✓ | 停服务（等回合收尾、断通道、退） |

- **agent 可操作命令**（`run_command` 工具接同一注册表）：**几乎全放开，仅 `/stop`
  禁止**（自保）；每次执行留审计（指令行 + 完整回执，见第四节），结果回给 agent。
  · agent 跑的命令**不产生用户气泡**——是工具调用，属于助手协议组，不污染时间线；
  · 已知风险：prompt 注入可能骗 agent 断频道/改配置（朋友发条消息）——demo 阶段
    接受，审计行可见；"动状态需 y/n 确认"做成可开的开关，留口子。

## 六、配置体系（~/.neoagent + yml）

```
~/.neoagent/                  # --home / NEOAGENT_HOME 可指走
├── config.yml                # 总配置（人看的）
├── channels/                 # 每频道一个 yml，文件名 = 频道名
│   ├── weixin.yml
│   └── feishu.yml
├── prompts/                  # 人设等（首启从包内拷入，用户改、升级不冲）
├── logs/latest.log
└── data/                     # 账本、转录、记忆、工作台、登录态、control.sock
```

**config.yml**——按"用户关心什么"分组，冷门项收 `advanced`；键名与注释无内部行话：

```yaml
# ~/.neoagent/config.yml
model:
  api_key: sk-xxxx            # 或环境变量 NEOAGENT_LLM_API_KEY
  name: deepseek-chat
  thinking: medium            # none/low/medium/high；聊天 /effort 也能热改

personality:
  prompt: prompts/messenger.md   # neoagent 的人设与说话方式

memory:
  dir: data/memory
  tidy_delay: 150             # 收工静默多久后整理记忆（秒）
  tidy_interval: 86400        # 定期整理节律（秒）
  tidy_lookback_days: 7       # 定期整理回看多少天
  tidy_thinking: medium       # 整理用的思考档位
  tidy_tool_rounds: 12        # 一次整理最多几轮工具

limits:
  max_tool_rounds: 90
  history_token_budget: 250000

advanced:                     # 一般不用碰
  workspace: data/workspace   # 工作台（工具默认目录、产出物落脚点）
  modellog_dir: data/modellog # 模型请求落盘（调试用；置空关闭）
  image_token_estimate: 1024
  bubble_gap: [0.5, 1.5]
  media: { max_bytes: 20971520, max_images_per_message: 4 }
  asr: { provider: xiaomi-mimo, model: mimo-v2.5-asr }
  safety:
    files_roots: ["~"]
    exec_roots: ["~"]
    exec_timeout: 60
    exec_max_output: 20000
    deny_patterns: [...]
```

**channels/*.yml**——文件名 = 频道名（时间线 `channel` 值就是它），`kind` 决定用哪个
adapter；这个结构顺便留出"多开同类频道"的口子：

```yaml
# ~/.neoagent/channels/feishu.yml
kind: feishu
enabled: true                 # /connect //disconnect 改的就是这行
app_id: cli_a94f...
app_secret: xxxx
owner: ""                     # 主人账号（将来配对后落这里）
```

- **ruamel.yaml 保注释写回**：指令热改（enabled / thinking）落盘不冲用户注释；
  改文件和改命令两条路殊途同归（生效值单源头）。
- 环境变量 `NEOAGENT_*` 覆盖惯例保留（密钥可不落盘）。
- **首启**：无配置 → 生成带注释骨架 + 三步指引（填 api_key → `/connect weixin` → 扫码）。
- **迁移**：老 config.toml + data/ 搬 ~/.neoagent 的一次性工具（`config convert`）
  已完成使命并删除（调参值没丢；要看去 git 历史）；此后**无版本迁移代码**，
  账本 schema 也没有版本化（表结构要改时得补迁移或宣布老库不兼容）。

## 七、connect 语义

- `/connect weixin`：没登录 → 扫码（QR 作为输出流推给所有连着的控制台）→ 启动
  adapter → **写入自启**（下次启动自动连）；
- `/disconnect weixin`：停 + 取消自启，**登录态保留**（再 connect 免扫码）；
- `/channels` / 无参 `/connect`：列出频道与状态；
- 运行中热插拔（起停 adapter）；`known_channels` 随之动态化。

## 八、前端无关内核（网页留位）

- 内核 = 三层信息模型 + 转录流 + 控制协议 + 命令注册表，**不绑任何前端**；
  终端是第一客户端；将来网页 = 第二客户端（小网关把转录流接到浏览器），
  内核一行不改；
- 触发做网页的条件：手机远程想看它在干嘛、或想直接看图（终端唯一硬缺口）；
- 远程暴露到公网涉及鉴权/TLS，到那时一起设计，这期 socket 只留本机 0600。

## 九、分批实施（每批验证、单独提交）

1. **配置系统**：home 目录解析、yml 加载（ruamel）、channels/*.yml、配置结构映射、
   `config convert` 迁移、首启骨架；
2. **命令注册表 + 双前端**：`/` 指令（聊天 + 控制台同语法）、回执两形态、
   `run_command` 工具与权限档；
3. **控制台与控制协议**：socket、serve/console/一体化三入口、转录存储与回放、
   prompt_toolkit 行式观感（banner/色板/工作行）、`/quiet` `/logs` `/history`；
4. **热插拔 + connect**：`/connect` `/disconnect` 运行中起停 + 写回 enabled、
   QR 流入控制台、`/status` 打磨；
5. **收尾**：打包入口、文档同步、手测。

smoke 不碰（用户约定）。开发期数据迁移：现仓库 config.toml 调参值与 data/ 经
`config convert` 搬入 ~/.neoagent，用户手里的 config.toml / prompts 文件不动不提交。

## 十、已知取舍与未来

- agent 命令几乎全放开 + 审计行（demo 阶段接受注入风险）；"确认开关"留口子；
- 图片在终端是占位符——看图去微信，或等网页前端；
- 全屏 TUI / 网页观感升级：转录在服务端，换渲染端即可，不推倒；
- `neoagent service install`（launchd/systemd 单元生成）；
- `/feed` 频道过滤、多终端权限、多用户/群聊：不在这批；
- 协议里模型内部代号不迁移（字节稳定 + 前缀缓存），红线只管渲染层与用户可见文案。
