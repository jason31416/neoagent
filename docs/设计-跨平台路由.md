# 跨平台路由与指令 —— 设计记录

> 日期：2026-10-01
> 状态：已实现
> 承接"砍 session"讨论：一条连续记录 + channel 属性 + 出口路由 + 指令层（/home）。
> 主人配对（/connect）、每平台独立配置等是后话，见第七节。

## 一、一条连续记录（session 语义退役）

- 产品的聊天记录是**完整、连续的一条**，没有"分段对话"概念——微信、飞书的来往都进同一条时间线；
- "session"降级为**机制层的桶名**（`app.TIMELINE_BUCKET = "main"`，账本分区列保留）：
  所有事件在入口归一到同一个桶，seq/msg# 编号、切点、整理游标全按桶走，自动跟上；
- 将来多用户/群聊 = 换分桶规则（比如按主人/按群分桶），账本与装配不动——这列就是那个口子；
- 一条无限长的记录靠 R 的**上下文切点**管长度（先落盘后切断）。

## 二、channel 属性（消息协议）

- 每条消息标 `channel="feishu"`（= 适配器 name：`feishu` / `weixin`），历史回放自带；
- **系统填、模型伪造剥掉**（与 id/time/sender 同类）；但它是**真开放属性**
  （与 replyTo 同级）——模型可写 `channel="feishu"` 强制把**这条**发到某频道；
- 模型写的 channel 不在启用频道白名单（`known_channels`）里 → 剥掉走默认；
- 定稿时把**最终落地的 channel 回填进标签**（气泡行也记）——发到哪在入库那刻已定，
  字节稳定不破，回放=生成形态。

## 三、出口路由（每条气泡独立解析）

1. 模型写了 `channel` → 用它；
2. 否则 → **记录里上一个用户说话的频道**（最后一个入站用户气泡的 channel）；
3. 查不到 → **home**。

- `/` 指令也是用户消息，算"用户最后说话的频道"（规则无特例）；
- 投递按气泡的 channel 分发到对应适配器，回复上下文用**该频道最近一条入站消息**；
  该频道还没有对话 → 发送失败降级（日志 + 说明）。

## 四、引用不跨平台

- 平台消息 id 是**平台局部**的（两平台可能撞 id）——入站引用解析限定同频道，
  `replyTo` 的真引用只在"目标气泡与投递同频道"时挂，跨频道**降级纯文本**（日志记）；
- channel 标进历史后模型自己看得见哪句在哪，天然少犯。

## 五、指令层（/ 开头，不进模型）

- 指令**与普通消息同构**：用户发的 `/home` 就是用户气泡（正常定稿入账、可被引用），
  唯一特殊是**不触发模型回合**；
- 系统回执也是**真气泡**：`<message sender="system" channel="feishu" id="msg#M" …>`
  ——类型 internal（上下文里是 system 角色）、方向 out、投递到指令来的频道并回填
  平台消息 id，**用户可以引用/回复它**；
- 模型下次看到"用户一条、system 答一条"自然理解，不伪装、不多解释；
- 解析器在 `core/commands.py`（纯函数，新增指令登记即可）；未知指令回执提示用法；
  `/` 开头的普通文本暂不设转义（接受此取舍）。

## 六、home（主动消息的默认出口）

- `/home` 无参 = 把**当前频道**设为 home；`/home <channel>` = 指定；
  回执永远写明"home 现在是 xxx"；
- 存账本 kv 表（运行时可写、重启不丢）；未设置时默认 = 记录里**第一条用户消息的频道**
  （当下等价于"第一个 connect 的频道"）；
- 主动消息（cron/提醒，将来）要求模型在 message 上写 channel；没写就发 home。

## 七、将来的口子（本批不做）

- `/connect <platform>` 主人配对码（`neoagent connect <platform>` CLI 生成）+ 每平台独立配置文件；
- 多用户/群聊：换分桶规则 + sender 归一（消息已带说话人，结构已兼容）；
- 主动消息通道（cron / jev）走 `inject_internal` 口 + channel 路由。
