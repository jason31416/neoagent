# 设计-主动性（proactive）

让 neoagent 自己决定何时请求自己。

产品文档"主动"章只当建议；本文是两轮对齐后的定案（含实现）。核心判断：
**主动性不是"多一个定时器"，而是一套"自我唤醒"机制 + 把"何时请求自己"的决定权交给 M。**

---

## 一、决定权怎么落到 M 手上

| 谁决定何时请求自己 | 机制 | 覆盖 |
|---|---|---|
| **M 自己（对话中）** | `schedule_wake` 工具：何时、什么理由、重复与否全由 M 定 | "明早提醒我带作业""这事一会再说""过两小时看下脚本" |
| **Jev 哨兵**（便宜代理） | 自适应周期哑探测，值得才叫醒 M；说不说仍由 M 定 | 没人提但值得惦记的事 |
| **外部事件** | E 完成 / watchdog / 进单聊 → 同一个 wake 接口 | 本期只留接口 |

决定（M 在对话里）→ 留账（tool_call 在账本）→ 到点自我唤醒（`<wake>` 入上下文）→ M 决定开不开口。哨兵只是把"决定"推广到没人提的事。

## 二、统一机制：Wake

```
注入 <wake> 块（role=user 的系统消息，无气泡）+ input_gen++ + 放行
    → M 醒来看到日程本的一张条：说话 / 干活（改期取消）/ 完全沉默
```

- **不打断进行中的 turn**（与 ingest 不同，不取消在飞模型）；会话在攒批窗口 → 随批一起开工（用户的话和唤醒由同一轮消化）；
- **唤醒永远落账本**（wakes 表 + `<wake>` 行）：叫没叫过、说过几次、用户接没接，全部现推，无 seen-set；
- **决定沉默也是决定，得留痕**：有思考就落 assistant 行（text 可空、气泡 0 条）——后续渲染和哨兵都看得出"到过点、想过、决定不提"。

### `<wake>` 块（协议）

```xml
<wake id="w37" source="alarm" at="2026-02-23 07:30" every="0 7 * * 1-5" time="2026-02-23 07:30">
  <note>面试带作业，简历在桌面</note>
</wake>
```

- 最小集：`id / source / at / every / note` + 系统填充 `time`（注入时刻）。**不带机械指针**（`msg#N` 这种指向已裁出上下文的东西是假线索）、不带内容注水（"你周日提过"这种由系统替 M 做的内容判断不可靠）；
- **note 是 M 给未来自己的便利贴**（自足、非用户口吻）：好「面试带作业，简历在桌面」，坏「提醒我带作业」「用户让我提醒他」；
- 块格式永远一个样：到点是它、补漏也是它——**补漏 = 同一条消息并列多个 `<wake>` 块**，M 一轮处置（补说/改期/静默作废），不逐条各响一次；
- `source`：`alarm`（M 排的闹钟）/ `probe`（哨兵判定，note 只是判定档位）/ `event`（留）。

## 三、闹钟（M 排的）

### 工具（要求写在描述里，不在人格里立规矩）

- `schedule_wake(note, at?, every?)`：`at`=一次性（绝对 ISO，自然语言由 M 换算）；`every`=重复（5 字段 cron）。用户说"一会再说/回头再看/晚点弄"→ 排 once 是它的主场景之一；
- `list_wakes` / `cancel_wake`：查/取消；改期 = 取消旧的 + 排新的；
- **cron 宽进严出**：只拦确定的语法错（字段数/越界/非法字符），语义不替 M 做主——`9 * * * *` 万一是真想每小时 09 分。纠错靠**回显下次触发时间**让用户当场纠；
- 回显例：`已排 w13：0 9 * * *（下次触发 2026-02-24 09:00）`。

### 调度与维护（产品文档点名的空缺在这里收口）

- wakes 表落盘（id/at/every/note/status/source/fired_count），重启不丢、崩溃不丢；
- 增删改全走 M 的工具 + 对话自然指令；一次性触发自动回收（fired）；重复项按 cron 续排，停机积压的过次不逐一补（块上 `at`=最近一次该响的时刻）；
- `/wakes` 让人也看得见清单；
- 启动补漏：过点项等 **home 频道连上**（不等所有平台）后一条消息合并注入。

## 四、哨兵（Jev 自主探测）

- **Jev 不生成文字**（`noul` 是标量不是文本）：判定档位（单 choice）就是它的全部输出，"该说什么"由 M 醒来看上下文定——这正好是产品文档"条件成立 ≠ 该开口"的形状；
- 判定题三档：`不值得 / 值得提醒 / 值得关心跟进`，例子校准（攒批那套方法）；confidence 低/调用失败 → 什么都不做（哑轮询无害）；
- **材料喂全（防重是数据不是规矩）**：最近流水（M 看到的原样）+ R 的记忆 + **pending 唤醒清单** + 机械统计（近 3 天叫醒次数、其后用户回没回）。闹钟在管的事 Jev 看得见，不重复叫醒；"提过没下文"的计数让"撒手"有依据；
- 节奏自适应：刚活跃 600s 一次，静默渐稀到 5400s；免打扰时段不探；**无每日上限**（防骚扰靠判断输入与 M 的沉默权，不靠计数硬闸）；
- 判定值得 → wakes 表落 `source="probe"`，走闹钟同一条注入路（叫醒动作落账）；
- 未配 `jev:`（顶层配置组）→ 哨兵整个不存在；闹钟不依赖 jev 照常跑。

## 五、撞车问题：闹钟 + 哨兵重复叫醒（复杂问题一）

场景：用户"下周一面试，提醒我带作业"→ M 排 w37（周一 07:30）→ 哨兵周四晚又"关心"一次 → 周一闹钟再响，一件事推三次。

为什么"提示词里说别重复"不行：①周四那句早被裁出上下文，M 无从对照；②哨兵看不到闹钟表，以为这事没人管；③反过来"有闹钟就禁言哨兵"会杀掉"前一晚提一嘴"这种有增量的关心——**区别在增量，不在有没有闹钟**。

结构解（已实现）：

1. **时间决策集中在创建时**：M 排闹钟时就把"要不要提前提一嘴"一并排掉（排两个 wake 或一个）；
2. **哨兵材料带 pending wakes 表**（喂数据）：实测 同素材对照——闹钟在管 → `不值得` conf 0.97；没人管 → `值得提醒` conf 0.54；
3. **撞在同一窗口就合批**，一轮消化；**沉默留痕**让 M/哨兵都看得见"已经想过/提过"。

反向协作例："那个脚本一会再说吧"→ M 当场 `schedule_wake`（once）→ wakes 表更新 → 哨兵从此不碰这事（登记即接管）。

## 六、发出去之后（复杂问题二）

**A. 发了不回**——按话的种类分：
- 告知类（硬闹钟）：沉默即成功，绝不追问；
- 关心类：一次沉默 ≠ 拒绝，连续沉默 = 现在不是时候——"提过 N 次没下文"的计数进哨兵材料，越提越不倾向提（一两次没下文就撒手）；
- 提问类：M 无状态不被卡住；用户回来时顺带一句或不提，靠同一条计数收敛。
- 认定保守：只有"主动消息后没有新 inbound"这一个事实，不做已读推断。

**B. 发的时候用户在聊别的**：
- 同窗撞批 → 一轮里先答正事、提醒作尾巴（或觉得不合时宜就咽回）；
- turn 跑到一半 → 不打断，收工后带全上下文补一句；
- 要紧闹钟（赶飞机）是"不打断"的反例——紧迫度是创建时信息，将来若需要把紧急度传到触发时刻，等实测撞上再定形态；
- 跨频道：按 home/最近频道发，M 可写 `channel` 属性。

## 七、出口与护栏

- 出口复用现有链（气泡 channel → 上个频道 → home）；主动出站兜底：重启后从账本重建路由事件（飞书 create 直发、微信走 context_token 缓存），发失败记账、M 下次补一句，不重试轰炸；
- 免打扰 `quiet_hours` 只管哨兵（闹钟/补漏照发——用户点名要的提醒不被静音）；
- 全留痕：wake 落账 + `/wakes` + 日志 source。

## 八、配置与命令

```yaml
jev:            # 顶层；不配 api_key = 哨兵不存在（settle.jev_* 是旧键，兼容映射）
  api_key: ""
  base_url: https://opencode.ai/zen/v1/systemone
  model: jev-1.13-free

proactive:
  enabled: true              # 哨兵开关（闹钟照常）
  quiet_hours: ""            # "23:30-08:00"：免打扰，只管哨兵
  probe_active_min: 600      # 刚活跃后下次探测（秒）
  probe_idle_max: 5400       # 静默渐稀的上限（秒）
```

- `/wakes`：清单（id/时刻/cron/note/状态），console 与聊天同一实现；
- `messenger.md` "主动（唤醒）"一节：`<wake>` 是什么、说不说自定、沉默合法、note 便利贴口吻、"一会再说"→ once wake。
